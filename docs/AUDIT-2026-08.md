## P0 — the plugin does not work for someone else

### P0-1 `render.sh` and `gate.sh` are dead on macOS system bash 3.2

`"${BRAND_ARG[@]}"` on an empty array is an unbound-variable error under `set -u` in bash < 4.4.
macOS ships 3.2.57 as `/bin/bash` and ships nothing newer.

```
$ /bin/bash scripts/render.sh examples/bar-card.example.json t /tmp/b32
scripts/render.sh: line 32: BRAND_ARG[@]: unbound variable
```

`gate.sh` is worse: it has no `set -e`, so it survives, gets an **empty** allowed-palette, and
reports all 8 legal brand hexes as `FAIL off-brand`. A correct card is failed by its own gate.

Invisible here because Homebrew bash 5.3 shadows `/bin/bash` in PATH, and CI is Ubuntu. CI never
invokes `render.sh` or `gate.sh` at all.

Affected: `render.sh:32`, `gate.sh:45,59`, `animate.sh:34,71,77`.

### P0-2 `animate.sh` can never produce an MP4

`animate.sh:87` gates the **master** render on the **GIF** pixel ceiling (36,152,320).

| spec | pixels | % of GIF budget |
|---|---|---|
| square master 1080x1080x165 @30 | 192,456,000 | 532% |
| portrait master 1080x1350x188 @30 | 274,104,000 | 758% |

It exits 1 before Remotion is invoked. `motion-check.py`'s own self-test *asserts* that
`check_budget(1080, 1350, 188, 30)` must fail, which is the exact call `animate.sh` gates on.
Both halves were written in the same session and the contradiction was never seen, because after
the gate was added only the refuses-without-storyboard path was retested.

Consequence: the `visual-motion` skill, `commands/animate.md`, and `plugin.json`'s headline
promise all document a path that has never run to completion.

### P0-3 the font check inspects only the artboard root

`qa-visual.cjs` asserts `getComputedStyle(artboard).fontFamily`. A child-element override sails
through. Injecting `font-family:Georgia` into `.head`:

```
qa-visual  -> QA PASS  6 checks     (exit 0)
gate.sh    -> ok [palette] ok [dashes] ok [impeccable]
CI guard   -> distinct font imports: 1
```

This check is named in two places as the regression test for the brand-font leak the whole
project was built around. It does not catch that leak.

### P0-4 the documented command runs neither the QA gate nor the claims ledger

`grep -c "qa-visual\|claims.py" scripts/render.sh` = **0**. The README leads with the
seven-assertion gate as "code, free, therefore always on"; the one command a user runs invokes
neither it nor the ledger. `qa-visual`'s first execution is inside Taste Loop B round 2, so no
documented step produces the round-1 `qaReport`/`feedPreview` that SKILL step 5 tells the agent
to hand the loop.

### P0-5 `render.sh` exits 0 when the gate fails

`bash gate.sh … || echo "(gate failed…)"` swallows the non-zero exit under `set -e`. A card with
an off-palette hex still renders and writes its shipped PNG. This is precisely the
"a gate that warns is a gate that gets scrolled past" failure the design claims to avoid.

### P0-6 the README's first command is not runnable

`git clone <this repo>` and `/plugin marketplace add <owner>/linkedin-visuals` are literal
placeholders, while `plugin.json` holds the real URL. Combined with a silent, output-suppressed
~100MB Chromium download that prints nothing for minutes, this is the most likely point for a
stranger to give up.

## P1 — integrity claims that are false

- **`calibrate.py --apply` writes `models.critic.model` but never `alias`** (`calibrate.py:205`),
  and `alias` is the only field `agent()` consumes (`taste-loop.js:36`). Calibration silently
  does not take effect, while `--apply` also deletes the honest "NOT pinned" note. Same class as
  the routing-inert bug commit `631e6a3` claimed to fix.
- **`log_usage` is never called.** `--report-cost`, sold in the README as "actual spend for a
  run", has no producer.
- **`calibrate.py:238` hardcodes the tier list** as an argparse default, so "the only file that
  names a model" is literally false and calibration is decoupled from `pipeline.json`.
- **`dashboard-card.py:49` `sparkline()` takes no data.** The flagship example renders three
  identical fabricated trend charts through a green gate, in a repo whose rule is "no fabricated
  numbers".
- **`motion-runtime.js` is referenced only by a code comment** in `remotion/src/Card.tsx`. It is
  a hand-synced second copy of the animation contract: two sources of truth for the timing
  behaviour, which is the drift bug the project's own philosophy warns against.
- **`gate.sh` has no `--self-test`** and is absent from the README's self-check list. It is the
  only gate `render.sh` runs, and the only enforcement script without two-sided proof.
- **`qa-visual`'s geometry engine, `forbidden-colors`, `forbidden-font` and `selector-count`**
  had no committed fixture. Two-sidedness was proven for the always-on core, unproven for the
  most complex opt-in logic. **Fixed** — the `--self-test` clean control now exercises all four
  (a textless `.deco` element for the font scan, a `.n` count assertion, an `rgb()` color the
  HEX check can't see, and a headline-above-body no-overlap check), and four seeds each fail on
  exactly one of them. Fixing it surfaced a real bug: the `no-overlap` check defaulted to the
  horizontal axis, so two vertically-stacked full-width blocks read as overlapping; the fixture
  now pins `axis: "vertical"`.
- **The 994,505-token figure has no committed artifact.** The four rows sum, but no ledger exists
  in the repo, so the one number labelled "measured" is unreproducible from the repo. **Resolved in
  docs** — the claim was reframed rather than the artifact fabricated: the "Measured cost" section is
  now "Cost of one run", the figure reads as one observed data point recorded 2026-08-07 and
  explicitly not reproducible from the repo, and the dollar line calls the tokens one observed run
  and the dollars an estimate. Fabricating a committed usage log would have been worse.
- **Taste Loop B's fixer edits the user's copy.** `taste-loop.js` `target=config` instructed an
  agent to "edit copy, wording, data", which crosses the README's "it will not invent your hook,
  it checks the words you chose" line. Constrained and low-stakes, but a real crossing. **Fixed** —
  `target=config` is now scoped to structural edits (shorten a field to fit, remove a duplicated
  stat, fill a genuinely missing required field) and carries an explicit HARD CONSTRAINT: "never
  rephrase, reword or invent the user's copy: this loop checks the words they chose, it does not
  write them."
- **`setup.sh` runs `npx playwright install chromium` without `--with-deps`**, unlike CI. A fresh
  Linux desktop can complete the download and still fail Chromium launch on missing system libs,
  and the printed fix does not resolve it.

## Portability beyond Claude Code

The package is spec-conformant, so a conformant client discovers both skills. Three hard limits:

- `commands/` is not an Agent Plugins v1 component type; `/visual` and `/animate` are ignored
  outside Claude Code (correct per §7, but it means the entry points differ).
- **Taste Loop B is a Claude Code `Workflow()`, and `calibrate.py` shells out to `claude -p`.**
  The rendering half is portable; the review half is Claude-Code-bound.
- **A plugin install alone cannot render — the clone is mandatory.** Every script path in
  `skills/visual-pipeline/SKILL.md` and `commands/visual.md` was repo-relative
  (`bash scripts/render.sh …`), and nothing used `${CLAUDE_PLUGIN_ROOT}`, so an installed-only
  plugin resolved those paths against the user's cwd and failed. **Fixed** — every documented
  invocation now uses `"${CLAUDE_PLUGIN_ROOT:-.}/scripts/render.sh"`: installed → the plugin dir,
  cloned-and-cd → `.` = the repo root. Siblings resolve via each script's own `$HERE`, so fixing
  the entry-point path is sufficient (verified: `render.sh`, `claims.py`, `brandkit.py` all
  resolved and ran from a foreign cwd via the plugin-root path).
